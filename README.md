# Real-Time ISL Recognition & Speech Assistant

Recognizes a defined vocabulary of 10 Indian Sign Language (ISL) signs from
live webcam video and speaks the recognized word/sentence aloud. Built as a
portfolio project exploring hand-landmark-based gesture recognition with a
sequence model (GRU), with both a local app and a browser-based frontend.

> **Scope note:** this is a sign *recognition* system for a fixed 10-word
> vocabulary, not a general-purpose ISL translator.


## How it works

```
Webcam → MediaPipe hand landmarks → normalize → 40-frame buffer
       → GRU classifier → confidence check → prediction smoothing
       → sentence builder → speech (pyttsx3)
```

- **Landmarks, not raw pixels:** each frame is reduced to 126 numbers
  (2 hands × 21 landmarks × 3 coordinates), which is far easier to learn
  from than raw video and keeps the model small (~140K parameters).
- **Sequence model:** signs unfold over time, so a GRU classifies a
  40-frame window rather than a single frame.
- **Normalization:** each hand is wrist-centered and scale-normalized
  (divided by wrist-to-middle-knuckle distance) so hand size and distance
  from the camera don't affect predictions.
- **Smoothing + confidence filtering:** a sign is only "confirmed" once
  several consecutive frames agree above an 80% confidence threshold,
  preventing flickering or low-confidence guesses.
- **Two interfaces:** a local OpenCV app (`app/live_app.py`) — the primary,
  recommended way to run this — and a browser-based Streamlit app
  (`app/app_streamlit.py`) using `streamlit-webrtc`, both sharing the same
  detection/model/smoothing logic. The Streamlit version works correctly
  but is noticeably more CPU-intensive (it runs hand detection, model
  inference, and WebRTC video encoding/decoding concurrently), so on
  CPU-only hardware it can feel less smooth than the local app.

## Vocabulary

| Category | Signs |
|---|---|
| Greetings/social | HELLO, THANKYOU, SORRY |
| Common needs | WATER, HELP |
| Responses | YES, NO |
| Emergency/urgent | EMERGENCY, PAIN, STOP |

## Dataset

- Self-recorded via webcam using MediaPipe Hand Landmarker (Tasks API).
- 10 signs × 2 recording sessions × ~25-65 samples/sign ≈ 500 sequences total.
- **Train/validation/test split by recording session**, not randomly: one
  full session is held out entirely as the test set, so reported accuracy
  reflects performance on video the model never trained on — not just a
  random shuffle of the same footage.
- Every sample was validated with a custom script that flags recordings
  where hand tracking dropped out for a large fraction of frames, and
  visually replayed as an animated stick figure to confirm correctness
  before training.

## Results

| Metric | Value |
|---|---|
| Test accuracy (held-out session) | 90.1% |
| Test loss | 0.325 |

Per-class performance was strong for 8 of 10 signs (precision/recall ≥ 0.92,
several at 1.00). Two signs showed a documented weakness: **PAIN** was
sometimes confused with **HELLO**, and **STOP** was sometimes confused with
**THANKYOU**. Visual replay of the raw samples showed these signs are
distinct as performed, so this is most likely session-to-session variation
in exact hand positioning rather than an inherently ambiguous sign — a
concrete, investigated finding rather than an unexplained error.

## Setup

```bash
python -m venv venv
venv\Scripts\activate          # Windows
# source venv/bin/activate     # Mac/Linux

python -m pip install -r requirements.txt
```

Download the MediaPipe hand landmark model and place it in the project root:
[hand_landmarker.task](https://storage.googleapis.com/mediapipe-models/hand_landmarker/hand_landmarker/float16/latest/hand_landmarker.task)

## Usage

```bash
# 1. Record training data (repeat per sign/participant)
python src/capture/record_dataset.py --label HELLO --participant p01 --samples 25

# 2. Validate recordings
python src/capture/validate_dataset.py --report

# 3. Preprocess into train/val/test arrays
python src/preprocessing/preprocess_dataset.py

# 4. Train the model
python src/models/train.py

# 5. Run the live app -- live_app.py is recommended (smoothest experience):
python app/live_app.py

# Or, for the browser version (functional, but more CPU-intensive --
# see Limitations below):
streamlit run app/app_streamlit.py
```

## Limitations

- Small, fixed 10-word vocabulary — not general ISL translation.
- Trained on a single signer (myself) across two recording sessions;
  accuracy on a genuinely different signer, skin tone, or camera setup is
  untested and likely lower.
- Sensitive to lighting and background clutter.
- No handling of ISL grammar/sentence structure — outputs isolated signs
  concatenated in recognition order, not grammatically structured sentences.
- The Streamlit version is not deployed to a public hosted link: cloud
  servers have no audio hardware, so the speech feature (a core part of the
  demo) would silently fail if hosted online. It's designed to be run
  locally, where speech output works correctly.
- The Streamlit/WebRTC interface is CPU-intensive (concurrent hand
  detection, model inference, and video encoding) and can run noticeably
  less smoothly than `live_app.py` on CPU-only hardware. `live_app.py` is
  the recommended interface for the best real-time experience; the
  Streamlit app is included to demonstrate a browser-based frontend, with
  this performance trade-off documented rather than hidden.

## Future improvements

- Add more participants for genuine cross-signer generalization testing.
- Add facial/non-manual cues (MediaPipe Holistic).
- Rotation-invariant landmark normalization.
- Investigate and resolve the PAIN/HELLO and STOP/THANKYOU confusion with
  more consistent, targeted re-recording.
- Mobile/on-device deployment.
